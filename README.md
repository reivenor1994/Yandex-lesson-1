# Декомпозиция монолита на микрофронтенды

## Уровень 1 - Архитектурное решение
Используется **Webpack Module Federation** по следующим причинам:

1. Единый стек технологий (React): Приложение разработано на React, и нет необходимости использовать разные фреймворки (например, React, Vue, Angular)
2. Упрощённая настройка для React-проектов:  Webpack Module Federation требует минимальной настройки для работы с React-проектами
3. Эффективное совместное использование кода между командами: Главной нашей целью является загрузка части приложения (модули, компоненты) из разных сборок во время выполнения, чтобы разные команды
   могли делиться кодом между собой уменьшая дублирование и упрощая обновления.
4. Single SPA больше подходит для проектов, где используются разные фреймворки (например, React, Vue, Angular): В нашем случае, где весь проект написан на React, Single SPA добавляет излишнюю сложность,
   так как его основное преимущество — поддержка мультифреймворковости — не востребовано.

## Уровень 2 - Структура микрофронтендов

### 🏠 Host Application (Основное приложение)

```text
host/
├── src/
│   ├── components/
│   │   ├── App.js           # Компонент в котором собирается весь контент
│   │   ├── Main.js          # Главный компонент для отображения профиля и карточек
│   │   └── ProtectedRoute.js # Компонент маршрутизации
│   ├── images/
│   │   ├── add-icon.svg   # Иконка добавления
│   │   └── edit-icon.svg  # Иконка редактирования         
│   ├── styles/
│   │   ├── page/            # Глобальные стили страниц
│   │   ├── profile/         # Стили профиля
│   │   └── content/         # Стили основного контента
│   └── utils/
│       └── api.js           # Базовые API-запросы
├── package.json
└── webpack.config.js
```

## Обоснование декомпозиции

1. **Разделение по функциональности**:
    - Специфичный функционал разбит по приложениям (аутентификация, профиль, контент)

2. **Повторное использование компонентов**:
    - Общие UI-элементы вынесены в shared-app

3. **Масштабируемость**:
    - Возможность подключения новых микрофронтендов без изменений host

4. **Безопасность**:
    - Изоляция чувствительной логики аутентификации
    - Защищённые маршруты в основном приложении
